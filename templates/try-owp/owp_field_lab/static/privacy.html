PRIVACY + DATA USE

Work-item data is not published by default.

The OWP Field Lab retains the data needed to operate the work lifecycle and evaluate the experiment. It does not require payment credentials or a public queue.

1

What is collected

Every submission includes the requested outcome, exact USD value signal, lifecycle decisions, evidence links and a one-way hash of the private customer token. PR work also stores public GitHub PR metadata and snapshots. Idea work stores the idea title and optional HTTPS context URL.

2

What is public

Aggregate queue capacity and generic protocol/service information. Individual work items, value signals and requested outcomes are not exposed through the public queue surface.

3

How data may be used

Source metadata, requested outcomes, value signals and lifecycle results may be retained and analyzed to evaluate and improve this field lab, OWP workflows and __OWP_OPERATOR_NAME__'s operating process. The service does not automatically publish the collected data as a public dataset.

4

Tracking link

The claim token is returned once in the URL fragment and stored by the service only as a SHA-256 hash. Anyone with the complete tracking link can act as that customer, so treat it like a password.

5

Abuse protection

The server keeps a short-lived in-memory client address key to limit submission attempts. It is not written to the work database or included in exports.

6

Handoff

Portable handoff exports intentionally omit the customer token and stored token hash. Before any public release of collected field data, the operator should review aggregation, redaction and anonymization for that release.
