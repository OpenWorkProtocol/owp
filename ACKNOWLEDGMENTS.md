# Acknowledgments

Open Work Protocol is developed through implementation feedback, security review,
and questions about where a portable work record ends and independently verifiable
evidence begins.

## Software Work Integrity security work

The RC3 Software Work Integrity work was influenced by a security question raised
by **[grogugo](https://github.com/grogugo)**: how can a returned patch be verified
as derived from the expected Git base rather than from substituted or modified
worker state?

That question led the profile to state five boundaries more explicitly: contract
Definition of Done consensus, Attempt-specific source commitments, provider delivery
claims, independent exact-result reconstruction/testing, and validator-attested
handoff state.

This acknowledgment recognizes the contribution to the security discussion. It
does not imply authorship of OWP, endorsement of the current design, responsibility
for its implementation, or agreement with every protocol decision.

Additional external standards and projects used as technical references are
listed in [docs/12-external-standards-alignment.md](docs/12-external-standards-alignment.md).
