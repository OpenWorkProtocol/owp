Software Work Integrity Profile

Verify the delivery independently.

For software work, the key question is whether the returned result is derived from the authorized base and is the exact state covered by its tests.

Failure case the profile addresses

expected base A
      |
untrusted worker
      +-- builds/tests benign B -> PASS
      +-- modifies B into C
      +-- claims base=A, result=C, tests=PASS

A SHA-shaped value and a PASS status remain claims until independently bound to the delivered result.

The trusted chain

  1. Contract consensus: customer, provider, orchestrator, and independent validator agree on the same Definition of Done digest.
  2. Attempt commitment: the exact repository, object format, base commit/tree, and any bounded acceptance delta are fixed before work.
  3. Provider execution: provider internals are not used as trusted validation state.
  4. Independent reconstruction: a validator-controlled clone/object path proves the expected base, result, ancestry, tree, exact diff, and scope.
  5. Exact-result testing: required acceptance runs against the exact delivered commit/tree, in a disposable environment when execution is required.
  6. Attestation: evidence names the exact result subject and validator policy.
  7. Handoff: the next Attempt starts only from that validator-attested result.

Use INDETERMINATE when evidence is unavailable

If required evidence cannot be obtained or a required command cannot safely be executed, the correct result is INDETERMINATE. That is different from both VALID and INVALID, and avoids treating missing evidence as successful validation.

What does not substitute for this check

  • a provider-reported base SHA or branch tip;
  • a green CI badge whose tested subject is not bound to the delivery;
  • a payment receipt;
  • a Git signature by itself;
  • an event-chain entry containing an unverified claim;
  • historical reputation;
  • a named validator that is actually controlled by the provider when independence is required.

Try OWP boundary

The Field Lab at try.openworkprotocol.org records a separately named validation actor and evidence, but that product experiment does not yet claim this complete profile. The site states that boundary explicitly.
