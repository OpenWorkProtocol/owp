Portable work.

Independent verification.

OWP gives humans, agents, and orchestrators a durable work boundary that remains useful across workers and providers. RC3 adds a software-integrity rule: delivery claims require independent verification.

For software work, an Attempt starts from an immutable source snapshot, delivery claims stay untrusted until independently reconstructed, and revisions inherit only validator-attested state.

Software integrity

Validate software delivery independently.

A reported SHA, green CI badge, or tests: PASS does not by itself establish which source was tested. OWP's optional Software Work Integrity Profile makes the trusted boundary explicit.

01 · Agree

Definition of Done first

Customer, provider, orchestrator, and independent validator acknowledge the same contract digest before it can be accepted.

02 · Bind

Every Attempt fixes its input

The exact repository identity, Git object format, base commit, and base tree are committed before execution—including revisions.

03 · Claim

Treat delivery as a claim

Provider-reported base/result SHAs, trees, checks, artifacts, and branch tips remain untrusted until independently verified.

04 · Reconstruct

Fresh validator-controlled state

The validator independently obtains the objects, checks ancestry/tree/diff/scope, and tests the exact delivered result.

05 · Attest

Evidence names its exact subject

Test and validator evidence bind to the delivered Git commit/tree so benign-test / malicious-delivery substitution fails.

06 · Handoff

Only validated state travels

A revision or provider change starts from the previous validator-attested result—not from provider narration or a mutable branch.

Work lifecycle

One durable contract, many possible workers.

OWP separates coordination truth from internal agent machinery. An orchestrator may use any models, tools, humans, MCP servers, or A2A transports behind the boundary.

1 · CONTRACTAgree the outcome

Portable intent, authority, Definition of Done.

2 · ATTEMPTBind execution

Provider/orchestrator plus exact source when selected.

3 · DELIVERYReturn evidence

Claims and artifacts enter the record without becoming truth by assertion.

4 · VALIDATEProve independently

Objective checks classify valid, invalid, or indeterminate.

5 · DISPOSITIONApprove, steer, hand off

The next worker inherits durable state rather than agent memory.

Experiment ≠ conformance.

No money is collected. The Field Lab does not claim independent OWP 1.0 interoperability or full RC3 Software Work Integrity validation. A named validation record is not a substitute for independently reconstructing and testing the exact Attempt-bound result.
